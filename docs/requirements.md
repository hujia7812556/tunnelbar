# TunnelBar 首版需求

项目名称：TunnelBar
整理日期：2026-11-13
阶段：首版代码已实现，正在按验收标准核验；构建和当前验证范围见项目 README

TunnelBar 是面向 macOS 的原生 SSH 隧道管理工具，用于集中管理开发时使用的端口转发。首版围绕已有 SSH 主机连接，将远端 Redis、Web 等服务映射到 Mac 本地；新增、停用或修改某条转发时，其他转发及其现有连接继续工作。

**当前只开发 Mac 版本。采用 Swift、SwiftUI，必要时使用 AppKit；连接能力由系统 OpenSSH 提供。独立实现应用，不以 SSH Tunnel Manager 的连接管理代码为底座。**

## 已确认的方向

- 应用名称为 TunnelBar，项目目录名为 tunnelbar。
- 原生 Mac 界面，提供菜单栏入口。
- 一份主机配置可以包含多条端口转发，共用一条 SSH 连接。
- 动态增删和修改转发，避免因单条规则变更重建整个 SSH 连接。
- 连接状态准确，断线能够恢复，进程清理只影响本应用拥有的连接。
- **每个主机支持“连接状态变化时发送系统通知”开关。**
- **每个主机支持“应用启动时自动连接”开关。**
- 暂不为 Windows、Ubuntu 引入共享核心、跨语言调用或平台抽象。

## 首版功能范围

### 主机配置

支持新增、编辑、删除主机配置，字段包括显示名称、SSH 主机地址或现有 SSH 别名、必要的用户名和 SSH 端口，以及可选的密钥文件。常用方式应能直接复用现有 SSH 别名。

主机级设置包括通知开关和应用启动自动连接开关。修改名称、通知偏好或启动偏好不应重启连接。

修改主机地址、用户名、认证参数等连接基础配置，需要重新建立连接才能生效；界面应说明影响，由用户明确执行重连。该行为与动态修改端口转发区分。

首版认证暂按现有密钥、SSH Agent 及可非交互完成的系统 SSH 配置实现。不能完成认证时显示原因，不在后台无限等待输入。交互式密码和验证码登录暂不纳入首版。

### 本地端口转发

每条规则包含名称或备注、本地监听地址、本地端口、远端目标地址、远端目标端口和启用状态。

本地监听地址默认使用 127.0.0.1；远端目标地址从 SSH 服务器所在网络解释。界面应清楚区分本机入口和远端目标，即使两侧地址都写 127.0.0.1，也不能让用户误以为是同一台机器。

端口列表提供每条映射的勾选框、已勾选数量，以及“全选／取消全选”。勾选表示启用映射，不代表已经成功监听；主机已连接时立即应用变更。每条映射可以填写备注，列表直接展示，并支持点击编辑、明确保存或取消。修改备注不改变连接或转发状态，也不重试其他失败规则。

用户可以新增、编辑、启用、停用和删除规则：

- 主机未连接时，保存配置；下一次连接应用所有启用的规则。
- 主机已连接时，新增规则应立即尝试生效，不中断其他规则。
- 新端口被占用或服务器拒绝转发时，明确显示该条规则失败，保留其他已生效规则。
- 停用或删除规则时，停止该规则接收新连接；已有业务 TCP 连接允许自然结束。不得因此重建整条 SSH 连接。
- 修改规则只调整该条规则。涉及相同监听地址和端口时，新旧规则无法同时监听，允许该条规则短暂停止接收新连接，但不能影响其他规则。
- 修改失败时尽可能恢复原规则，并如实显示当前结果；不能将仅已保存的配置显示为已生效。
- 通过明确的保存或应用操作提交编辑，避免每次输入、切换焦点都触发连接操作。

首版只实现本地转发。远程转发和 SOCKS 代理列为后续候选，不提前实现。

### 连接管理与状态

提供主机级连接、断开和重连操作，并分别展示主机状态和每条规则的运行结果。

主机至少区分未连接、连接中、已连接、重连中和失败；规则至少区分未启用、等待连接、已监听和失败。SSH 已认证、端口已监听、目标服务可访问是不同事实：目标 Redis 停止工作，不等于 SSH 连接已经断开。

启动 SSH 进程、PID 存在或某个端口被其他程序占用，都不能单独作为“连接成功”的依据。显示错误时提供可理解的原因，例如认证失败、主机不可达、主机指纹不匹配、端口占用或转发被拒绝。

同一主机不应因重复点击或重连任务并发而创建重复连接。旧连接的退出事件不能覆盖新连接的状态。

### 断线自动重连

对当前处于用户期望连接状态的主机，在网络断开、SSH 异常退出或睡眠恢复后尝试重新连接，并恢复已启用的转发规则。

重试应有等待间隔并避免密集循环。明确的认证或主机指纹错误，应显示需要用户处理的原因，避免无意义地持续重试。

用户主动断开后，本次运行中停止该主机的自动重连。退出应用后不应留下自行重新连接的后台任务。

**自动重连恢复的是 SSH 连接和转发监听，无法恢复断网前已断开的业务 TCP 连接。** 数据库客户端、浏览器或其他调用方需要自行重连。

### 连接状态通知

这是每个主机独立保存的开关。启用时申请 macOS 通知权限；权限被拒绝时提供可见说明及系统设置入口，不影响连接功能，也不反复弹出授权请求。

首版建议通知以下有意义的变化：

| 场景 | 通知行为 |
| --- | --- |
| 首次连接成功 | 发送一次成功通知 |
| 用户主动断开已连接主机 | 发送一次断开通知 |
| 已建立连接意外中断 | 发送一次中断通知 |
| 自动重连恢复成功 | 发送一次恢复通知 |
| 首次连接失败 | 发送一次失败通知 |
| 正在连接、每轮重复重试、重复收到相同状态 | 不重复通知 |
| 仅调整端口规则或关闭主窗口 | 不发送主机断开通知 |
| 用户退出应用 | 不为全部主机逐条发送断开通知 |

通知内容只包含必要的主机显示名称、状态和简短原因，不显示密码、密钥或敏感配置。关闭某个主机的通知开关，不改变其连接和重连行为。

### 应用启动时自动连接

这是每个主机独立保存的开关。TunnelBar 启动并加载配置后，自动连接开启此项的主机；未开启的主机保持未连接。

启动自动连接和断线自动重连是两个概念：

- 开启启动自动连接的主机，在下一次应用启动时尝试连接。
- 未开启启动自动连接的主机，被用户手动连接后，意外断线仍应自动重连。
- 手动断开不会自动清除已保存的启动偏好；本次运行保持断开，下次启动按该偏好处理。
- 修改启动偏好本身不应立即连接或断开当前主机。

“应用启动时自动连接”不等于“登录 Mac 时启动 TunnelBar”。后者暂不列入已确认首版范围。

### 界面与应用生命周期

主窗口采用主机列表和详情区域。详情展示主机状态、连接操作、端口转发表格，以及通知和启动自动连接两个开关。菜单栏提供状态概览、主机连接或断开入口，以及打开主窗口和退出应用入口。

关闭主窗口只隐藏窗口，菜单栏和现有连接继续工作。明确退出应用时，结束本应用管理的连接和任务，保存配置；不得按端口或宽泛的进程名匹配终止其他 SSH 会话。

新增主机的两个偏好开关暂建议默认关闭，由用户按需开启；这一默认值可以在界面评审时调整。

### 配置与错误信息

配置在本机持久化，包含主机、转发规则、启用状态和两个主机级开关。程序启动后能够恢复这些配置。

配置保存采用原子替换等方式避免半写入。配置读取失败时明确报错并保留原文件，不能把空配置自动写回覆盖旧配置。

首版不保存登录密码或私钥内容。配置可保存密钥路径，实际认证交给系统 SSH 和已有 Agent。错误信息和日志应过滤敏感内容，并限制日志增长。

每个主机提供“详细信息…”入口，展示连接配置和按时间排列的连接日志，记录连接成功、断开、重试等待、端口启停、转发失败及回滚结果。日志按主机独立保留最近 300 条并本地持久化，支持跟随最新和复制；日志写入失败不影响 SSH 连接。删除主机时一并删除该主机日志。首版不记录 SSH 原始输出或业务请求内容；实际协商的算法及主机指纹暂不展示。

## 实现边界

目录先按界面、连接管理和配置保存组织，使用一个 Mac 应用工程即可。暂不拆分跨平台库、插件系统、独立守护进程或复杂后端接口。

采用系统 OpenSSH 的连接复用和控制通道，在已有连接中动态添加或取消转发。OpenSSH 官方提供 forward、cancel 等控制命令；具体参数和用户现有 SSH 配置的交互，应先通过小范围技术验证。[OpenSSH 官方手册](https://man.openbsd.org/ssh.1#O)

连接及控制套接字由 TunnelBar 独立拥有。复用用户认证配置不代表接管用户在终端或其他应用中创建的主连接。应用不能仅凭旧 PID 文件中的数字就强杀进程，也不能使用按端口匹配的批量清理。

主机指纹校验不能默认关闭。首版遇到未知主机或指纹变化时，应明确停止并提示处理；首次指纹确认界面暂不要求实现。

对已有 SSH 配置中的 LocalForward、RemoteCommand、ControlMaster 等可能冲突的指令，应在技术验证中明确处理方式。首版不宣称兼容全部 OpenSSH 配置组合。

## 首版验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 同一主机建立两条本地转发 | 两条都可用，共用一条由应用管理的 SSH 连接 |
| A02 | 保持一条业务 TCP 长连接，同时新增转发 | 新转发生效，原连接能够继续收发数据 |
| A03 | 新增已被占用的本地端口 | 新规则明确失败，其他规则和已有长连接不受影响 |
| A04 | 停用或删除一条转发 | 停止该规则的新连接，其他规则继续工作；已有连接行为符合说明 |
| A05 | 修改单条规则、名称或偏好 | 仅必要范围发生变化；其他规则不中断，修改名称和开关不重连 |
| A06 | 快速连续连接、断开、重连 | 无重复连接、遗留任务或旧事件覆盖新状态 |
| A07 | 断网、SSH 异常退出或睡眠恢复 | 状态准确，能够按策略恢复转发，不承诺恢复旧 TCP 会话 |
| A08 | 用户手动断开 | 本次运行不自动连接回来；持久化启动偏好保持不变 |
| A09 | 分别开启和关闭两台主机的通知 | 通知遵循各自主机设置，连续重试不刷屏；拒绝系统通知权限不影响连接 |
| A10 | 重启应用 | 配置和两个开关保留；只自动连接开启启动偏好的主机 |
| A11 | 关闭窗口和退出应用 | 关闭窗口不断开；退出仅清理本应用资源，其他 SSH 会话不受影响 |
| A12 | 配置损坏、认证失败、指纹变化 | 明确显示失败，不误报成功，不覆盖原配置，不关闭指纹校验 |

先对这些关键行为进行必要验证。SSH 集成验证使用可控测试服务；对现有业务连接的无中断要求，应以持续收发数据验证，不能只看 PID 或绿色图标。

性能方面先记录空闲、单主机多端口和断线重试时的 CPU 与内存占用，不预设“必然比 Core Tunnel 更省内存”的结论。

## 待后续明确与暂缓内容

工程最低运行目标暂定 macOS 13，使用其系统 OpenSSH 支持的连接控制选项；当前只在用户现有 Mac 上验证，尚未在 macOS 13 实机验收。应用图标、安装分发方式及是否需要登录 Mac 时启动应用，留到后续界面评审确定。

交互式密码和验证码、远程转发、SOCKS、专用跳板机编辑界面、多机同步、自动更新、Windows 和 Ubuntu 支持均暂缓。已有 SSH 别名中的跳板配置是否可直接使用，纳入系统 SSH 兼容性验证，不先扩展为新的管理功能。
