# TunnelBar

轻量的 macOS 原生 SSH 隧道管理工具，使用 SwiftUI、AppKit 和系统 OpenSSH，无第三方应用依赖。

首版已实现主机和本地转发管理、菜单栏、动态增删转发、断线重连，以及每个主机独立的系统通知和启动自动连接开关。需求见 [docs/requirements.md](docs/requirements.md)。

## 构建和运行

在项目目录运行：

~~~sh
make build
open build/TunnelBar.app
~~~

完整 Xcode 可用时使用 TunnelBar.xcodeproj；否则直接使用系统命令行工具中的 Swift 编译器和 macOS SDK，组装并本地签名应用。当前设备已经通过命令行路径构建和启动，不必等待完整 Xcode。

发布构建使用 `make build CONFIGURATION=Release`，开启编译优化；默认 `make build` 保留 Debug 配置。

构建默认使用登录钥匙串中的本机自签名代码证书 `TunnelBar Local` 及对应私钥。Makefile 和 Xcode 工程固定使用同一证书；如果证书或私钥被删除、更换，构建会失败，需要重新配置签名，并可能重新授予系统权限。该证书未加入系统全局信任，也不能用于 Apple 公证；其他 Mac 可能拒绝打开使用该证书签名的应用。

其他开发者可传入自己证书的名称或指纹，例如 `make build SIGNING_IDENTITY="证书名称"`。临时本机测试也可使用 `make build SIGNING_IDENTITY=-`；临时签名在更新程序后可能需要重新授权。使用 Xcode 时也需在工程签名设置中选择自己的证书。

应用图标位于 TunnelBar/Resources/AppIcon.icns，包含 16–1024 像素的标准尺寸；AppIcon.png 保留透明背景原图。命令行和 Xcode 构建均将图标打包到应用中。

最低运行目标为 macOS 13，使用系统 OpenSSH 的连接复用功能；当前构建环境为 macOS 27.2、OpenSSH 10.5p1、独立 Command Line Tools 27.2 和 Swift 6.4.2。当前 CLT 安装包未包含 SDK 27.2 所需的 SwiftUIMacros，Makefile 因此使用随包提供的 macOS 26.5 SDK，已重新构建通过，无需完整 Xcode。尚未在 macOS 13 实机验证。

## 使用方式

添加主机时可直接填写现有 SSH 别名。用户名、端口和密钥留空时沿用系统 SSH 配置。首版使用已配置的密钥或 SSH Agent，不提供密码、验证码弹窗。未知主机指纹须先在终端核实；应用不会关闭主机指纹校验。

一个主机可以配置多条本地转发。连接后新增、停用、删除或修改某条规则，不重启其他规则；修改失败时尝试恢复原规则。已监听表示本机入口建立，不代表远端服务一定可用。

在端口列表直接勾选需要启用的映射，也可使用“全部启用／全部停用”。每条映射的备注可在列表点击编辑，保存或按回车后生效；按 Esc 取消并保留原备注。只改备注不会调整监听或触发失败规则重试。

端口列表使用 macOS 原生表格，提供可调整的列宽、双击编辑、右键操作和键盘删除；勾选启用与行选择相互独立。主机设置和日志按需展开，失败信息留在表格下方。标题栏提供侧栏切换和添加主机，支持 ⌘N 新建主机、⌃⌘S 切换侧栏和 ⌘K 连接／断开当前主机。

应用图标保留蓝青渐变、隧道和双向箭头，使用几何源文件绘制连续圆角和透明边缘；修改 `scripts/generate-app-icon.swift` 后运行 `make icon`，再构建应用。菜单栏使用随系统外观变化的单色符号。

“应用启动时自动连接”按主机保存；手动连接的主机也会在意外断线后重试。手动断开则停止本次运行中的自动重连。断线恢复重新建立监听，不会恢复原来的业务 TCP 会话。

通知按主机开启，首次开启申请系统权限，连续重试不重复通知。关闭窗口后菜单栏和连接继续运行；明确退出应用会关闭自身管理的连接。

点击窗口左上角关闭按钮时，主窗口和 Dock 中的运行图标会隐藏；点击菜单栏中的 TunnelBar，再选择“打开 TunnelBar”可重新显示窗口和 Dock 图标。

开启主机通知后，其端口转发开始监听、停止监听、SSH 意外中断导致监听停止或建立监听失败时也会通知；重复的同一监听失败不会反复通知。修改规则失败后如果成功恢复原监听，会分别提示恢复和失败。通知反映本地监听状态，不代表远端服务可用，也不跟踪每个业务客户端的连接。

展开“连接日志”即可查看带时间的日志，也可从主机操作菜单打开“连接详情…”查看连接配置。日志记录连接、断开、自动重试、转发启停及失败回滚，每台主机保留最近 300 条，保存于同目录的 connection-logs.json，应用重启后仍可查看；支持跟随最新和复制日志。日志独立于系统通知开关，不记录密码、私钥、SSH 原始输出或转发业务内容。当前详情展示配置值，尚未采集实际协商的加密算法和主机指纹。

配置保存于 ~/Library/Application Support/TunnelBar/hosts.json，仅包含主机及转发元数据。读取失败时保留原文件并禁止覆盖。应用独立持有自己的 SSH 控制套接字，不接管终端或其他应用的连接。

## 关键行为验证

~~~sh
make check
~~~

这一组检查额外使用系统 Python 3 和 sshd，均只用于测试。在回环地址启动临时 SSH 与 echo 服务，使用临时密钥，不修改用户 SSH 配置或系统 sshd 配置。macOS sshd 的认证沙箱无法在部分受限执行沙箱内启动，需要在普通终端执行。

检查覆盖同一条业务 TCP 长连接在新增、取消、端口冲突、修改失败回滚和偏好更新之后继续收发；并验证真实服务中断后的自动重连、快速连接切换、主动断开不重连，以及 OpenSSH 取消失败的判定。

## 项目结构

~~~text
TunnelBar/
  Models.swift          主机、规则和运行状态
  ConfigStore.swift     配置读取与原子保存
  SSHTransport.swift    自有 SSH 进程与控制命令
  TunnelManager.swift   连接生命周期、动态转发与重试
  AppModel.swift        界面和后台之间的状态同步
  Notifications.swift  系统通知权限及状态通知
  Views.swift           主窗口和编辑表单
  AppDelegate.swift     窗口、菜单栏及退出清理
  main.swift            应用入口
TunnelBar.xcodeproj/    单一 Mac 应用工程
Tests/                 一组本地 SSH 集成检查
docs/                  需求文档
~~~

当前未实现远程转发、SOCKS、登录 Mac 时自启动、跨平台、云同步或自动更新。已在本机验证应用重启后自动恢复连接及端口监听；系统通知实际展示和睡眠恢复仍需桌面场景验收，完整 Xcode 构建路径未经验证。
